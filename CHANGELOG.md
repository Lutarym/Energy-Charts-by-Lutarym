# Changelog

## v2.3.0

- English: Every card checked against the Home Assistant source code and against a faithful replica of the statistics query, with expected values computed straight from hourly data. Seven calculation errors fixed. Months were assigned in the browser's time zone, but Home Assistant forms its days and months in its own (`hass.config.time_zone`): with a browser west of the server every bar slid one month forward and January dropped out of the year. All boundaries are now calculated in the server's time zone. The query window ended on 1 January of the following year, which Home Assistant moves to 1 February for monthly statistics, so the next January came along; it now ends on the last moment of the year. Charging efficiency counted hours without a grid value as grid-free, so every gap in the grid sensor raised it (in the test 23.2 % instead of 22.3 % for a year); such hours are now left out. A grid or heat sensor in MW, mW, GW or BTU/h was not recognised as power and charging efficiency stood at 100 %; Home Assistant now converts every power unit to kW itself. The yearly average of self-sufficiency and battery counted every month the same, so a November with three days weighed as much as a full October; it is now weighted by time. The electricity overview compared the year so far including today against full days of the previous year, and a meter that only started during the previous year against an incomplete year (+30.3 % instead of −0.6 % in the test); the comparison now runs over complete days and, for a new meter, starts on its first calendar day in both years. A room with 0 kWh showed a dash instead of 0, and automatic room detection added feed-in, generation and single-phase meters of the same area to its consumption (809 instead of 553 kWh in the test); they are now excluded. Further pitfalls: a base fee written as "12,5" showed "NaN EUR"; prices, fees, kWp and other numbers now accept a decimal comma. `years_back` with text or a fraction no longer empties the chart. All numbers follow the number format of the Home Assistant profile instead of a fixed dot or the browser language. Results of an outdated request can no longer overwrite newer data, and peak power, kilometres and temperature load in parallel with the main series. Removed the unreachable `getConfigForm` and an unused function. The README described charging efficiency as 1 − grid ÷ charging per month; it now describes the hourly calculation the card actually performs. The editor shows the installed version at the bottom.

## v2.2.0

- English: The growing preview is gone for good, because the cause is gone rather than patched. The bar-chart presets used to take their chart height from the card height measured by the resize observer. That is a loop: the card redraws, grows a little, the observer reports the new height, the card grows again. Wherever a frame takes its own height from its content, and every preview does, the loop never ends. 2.1.1 and 2.1.2 tried to make the arithmetic exact enough to settle, which only held for the cases I could reproduce. The card no longer looks at its own height at all. The chart height now comes from the row count in the configuration (`grid_options.rows`, or the older `layout_options.grid_rows`), and otherwise from the card width, both fixed inputs. Dragging a card taller in a sections dashboard still works, because Home Assistant writes the new row count into the configuration. The row count is converted exactly as the sections grid does, rows × (56 + 8) − 8 pixels.

## v2.1.2

- English: The preview still grew without end for some themes; 2.1.1 did not go far enough. The remainder next to the chart was measured from the card's parts, which misses anything those parts do not contain, such as a margin or padding added by a theme. It is now measured as the distance from the card's edge to the chart, so nothing in between can be left out. Reproduced in the browser: with extra border and padding on the card, the old calculation went from 465 to 1329 to 2409 pixels and kept climbing, while the new one settles at once. Two further safeguards: if the measured height is exactly the height the card produced itself, nobody is imposing a height and the chart keeps the height that follows from the card's width; and the rooms and overview presets no longer carry `min-height: 100%`, which had the same self-lifting effect in a frame whose height follows its content.
